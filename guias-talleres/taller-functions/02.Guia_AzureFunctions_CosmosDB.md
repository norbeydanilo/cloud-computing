# Reseñas de libros con Azure Functions y Cosmos DB
## Un sistema de comentarios serverless con base de datos documental

**Computación en la nube**

---

## Contexto y decisiones de diseño

El sistema de biblioteca que construimos en el curso usa **PostgreSQL en una VM** para almacenar libros con esquema fijo: isbn, titulo, autor, año, disponible. Esa decisión fue correcta porque los libros tienen estructura predecible y relaciones claras.

Las **reseñas de lectores** son un caso distinto. Dos lectores pueden enviar información completamente diferente:

```json
{ "isbn": "978-0-06-112008-4", "lector": "Juan", "valoracion": 5, "comentario": "Obra maestra." }

{ "isbn": "978-0-06-112008-4", "lector": "María", "valoracion": 4,
  "comentario": "Excelente.", "etiquetas": ["clásico", "colombia"],
  "citaFavorita": "El mundo era tan reciente...",
  "recomendadoPara": ["adultos", "amantes de la historia"] }
```

Guardar esto en PostgreSQL obligaría a columnas nullable o tablas adicionales para cada campo opcional. En Cosmos DB cada documento se guarda tal como llega, sin esquema fijo. Eso es exactamente el caso de uso de una base de datos documental.

**¿Por qué Functions y no Express + VM para las reseñas?**

Los lectores no envían reseñas a las 3 AM ni de forma continua. El tráfico es intermitente: picos cuando se publica un libro nuevo, silencio el resto del tiempo. Tener un servidor siempre encendido para recibir escrituras ocasionales es costoso e innecesario. Functions escala a cero cuando no hay actividad y se activa en milisegundos cuando llega una reseña. Se paga solo por las ejecuciones reales.

**Lo que vamos a construir:**

```
POST /api/EnviarResena          → guarda una reseña en Cosmos DB
GET  /api/ObtenerResenas/{isbn} → devuelve todas las reseñas de un libro
Timer (lunes 8 AM)              → genera el resumen semanal de los libros más reseñados
```

Tres funciones, tres triggers distintos, un solo servicio administrado de datos.

### 1.3 Crear la base de datos y el contenedor

Cuando aparezca "La implementación se completó", ve al recurso.

1. En el menú lateral, haz clic en **"Explorador de datos"**
2. Haz clic en **"Nuevo contenedor"**
3. Completa el formulario:

| Campo | Valor |
|---|---|
| **Id. de base de datos** | Selecciona "Crear nueva" → escribe `biblioteca` |
| **Id. de contenedor** | `resenas` |
| **Clave de partición** | `/isbn` |
| **Rendimiento de la base de datos** | Manual → `400` RU/s |

> **¿Por qué `/isbn` como clave de partición?**
> Cosmos DB distribuye los documentos entre particiones para escalar horizontalmente. La clave de partición determina cómo se agrupan. Elegimos `/isbn` porque la consulta más frecuente es "todas las reseñas de un libro específico". Esa consulta siempre irá a una sola partición, lo que la hace eficiente.

4. Haz clic en **"Aceptar"**

En el Explorador de datos verás la estructura: `biblioteca` → `resenas`. Puedes hacer clic en "Elementos" para ver los documentos (ahora vacío).

### 3.3 Verificar y corregir el function.json

El portal a veces genera el `function.json` con dos errores que impiden que el binding funcione. Hay que revisarlo antes de probar.

1. Ve a **"Código y prueba"**
2. Haz clic en el selector de archivo (donde dice `index.js`) y selecciona **`function.json`**
3. Busca el bloque del binding de Cosmos DB. Puede tener este aspecto con dos problemas:

```json
{
  "name": "outputDocument",
  "direction": "out",
  "type": "cosmosDB",
  "methods": [],              ← PROBLEMA 1: este campo no existe en Cosmos DB, borrar
  "databaseName": "biblioteca",
  "collectionName": "resenas", ← PROBLEMA 2: debe ser containerName, no collectionName
  "createIfNotExists": true,
  "connectionStringSetting": "CosmosDB"
}
```

4. Corrígelo para que quede exactamente así:

```json
{
  "name": "outputDocument",
  "direction": "out",
  "type": "cosmosDB",
  "databaseName": "biblioteca",
  "containerName": "resenas",
  "createIfNotExists": true,
  "connectionStringSetting": "CosmosDB"
}
```

Los dos cambios críticos son:
- Eliminar la línea `"methods": []` — el portal la inserta por error en los bindings de Cosmos DB
- Cambiar `"collectionName"` por `"containerName"` — Functions v4 usa `containerName`; con `collectionName` el binding no encuentra el contenedor y falla con el error `Value cannot be null (Parameter 'containerId')`

5. Haz clic en **"Guardar"**

### 3.4 Código de la función

Ve a **"Código y prueba"** y reemplaza el contenido de `index.js`:

```javascript
module.exports = async function (context, req) {

    const resena = req.body;

    // Validación de campos obligatorios
    if (!resena || !resena.isbn || !resena.lector || !resena.valoracion) {
        context.res = {
            status: 400,
            body: 'Los campos isbn, lector y valoracion son obligatorios.'
        };
        return;
    }

    if (resena.valoracion < 1 || resena.valoracion > 5) {
        context.res = {
            status: 400,
            body: 'La valoracion debe ser un número entre 1 y 5.'
        };
        return;
    }

    // Construir el documento a guardar en Cosmos DB
    // El campo 'id' es obligatorio en Cosmos DB como identificador único del documento
    const documento = {
        id: `${resena.isbn}-${Date.now()}`,
        isbn: resena.isbn,
        lector: resena.lector,
        valoracion: resena.valoracion,
        comentario: resena.comentario || null,
        fechaCreacion: new Date().toISOString(),
        // Cualquier campo adicional que envíe el cliente se guarda sin modificar
        ...resena
    };

    // Asignar al binding de salida: Azure escribe el documento en Cosmos DB automáticamente
    context.bindings.outputDocument = documento;

    context.log(`Reseña guardada: ${documento.id}`);

    context.res = {
        status: 201,
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(documento)
    };
};
```

Haz clic en **"Guardar"**.

> **`context.bindings.outputDocument`:** es el binding de salida que configuramos en el paso anterior. En el momento que la función termina, Azure toma ese objeto y lo escribe en Cosmos DB. No hay código de conexión, no hay `await collection.insert()`. Esto es lo que Azure llama una salida declarativa: declaramos qué queremos guardar y Azure lo hace.

### Función ObtenerResenas — todas las reseñas de un libro

#### 4.1 Crear la función

1. En la Function App, ve a **"Funciones"** → **"+ Crear"**
2. Selecciona **"HTTP trigger"**
3. Nombre: `ObtenerResenas`
4. Nivel de autorización: `Anonymous`
5. Haz clic en **"Crear"**

#### 4.2 Configurar el function.json

Ve a **"Código y prueba"**, abre `function.json` y **reemplaza todo el contenido**:

```json
{
  "bindings": [
    {
      "authLevel": "anonymous",
      "type": "httpTrigger",
      "direction": "in",
      "name": "req",
      "methods": ["get"],
      "route": "resenas/{isbn}"
    },
    {
      "type": "http",
      "direction": "out",
      "name": "res"
    },
    {
      "name": "resenas",
      "direction": "in",
      "type": "cosmosDB",
      "databaseName": "biblioteca",
      "containerName": "resenas",
      "sqlQuery": "SELECT * FROM c WHERE c.isbn = {isbn}",
      "partitionKey": "{isbn}",
      "connectionStringSetting": "CosmosDB"
    }
  ]
}
```

> **¿Por qué `partitionKey`?** La clave de partición del contenedor es `/isbn`. Sin especificarla en el binding, Cosmos DB ejecuta un cross-partition query que puede devolver resultados vacíos aunque haya documentos. Con `"partitionKey": "{isbn}"` la consulta va directo a la partición correcta y el resultado es confiable.

Haz clic en **"Guardar"**.

#### 4.3 Código de la función

Abre `index.js` y reemplaza el contenido:

```javascript
module.exports = async function (context, req) {

    const isbn = req.params.isbn;
    const resenas = context.bindings.resenas;

    if (!resenas || resenas.length === 0) {
        context.res = {
            status: 404,
            body: `No se encontraron reseñas para el ISBN ${isbn}.`
        };
        return;
    }

    const promedio = (
        resenas.reduce((suma, r) => suma + r.valoracion, 0) / resenas.length
    ).toFixed(1);

    context.res = {
        status: 200,
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            isbn: isbn,
            totalResenas: resenas.length,
            promedioValoracion: parseFloat(promedio),
            resenas: resenas.map(r => ({
                id: r.id,
                lector: r.lector,
                valoracion: r.valoracion,
                comentario: r.comentario,
                fechaCreacion: r.fechaCreacion
            }))
        })
    };
};
```

Haz clic en **"Guardar"**.

- Método: **GET**

Debes recibir **200 OK** con el total de reseñas, el promedio y el listado. Observa que la respuesta incluye el campo `id` de cada reseña — lo usaremos para llamar a `ObtenerResena`.

## Parte 5: Función ResumenSemanal (Timer)

Esta función se ejecuta automáticamente todos los lunes a las 8 AM, lee todas las reseñas de la semana anterior desde Cosmos DB, las agrupa por libro y genera un ranking de los más reseñados.

### 5.1 Crear la función

1. En la Function App, ve a **"Funciones"** → **"+ Crear"**
2. Selecciona **"Timer trigger"**
3. Nombre: `ResumenSemanal`
4. Programación: `0 0 8 * * 1` (lunes a las 8:00 AM)
5. Haz clic en **"Crear"**

### 5.2 Agregar el binding de entrada desde Cosmos DB

1. Ve a **"Integración"**
2. En la sección **"Entradas"**, haz clic en **"+ Agregar entrada"**
3. Selecciona **"Azure Cosmos DB"**
4. Completa el formulario:

| Campo | Valor |
|---|---|
| **Nombre del parámetro del documento** | `todasLasResenas` |
| **Nombre de base de datos** | `biblioteca` |
| **Nombre de colección** | `resenas` |
| **Consulta SQL** | `SELECT * FROM c` |
| **Conexión de cuenta de Cosmos DB** | Selecciona la misma conexión `CosmosDB` |

5. Haz clic en **"Aceptar"**

6. Abre `function.json` y aplica las mismas correcciones: cambia `collectionName` por `containerName` y elimina `"methods": []` si aparece.

> La consulta trae todos los documentos; el filtro por fecha de la última semana lo hacemos en el código JavaScript. Esto es más flexible que intentar calcular fechas dinámicas dentro de la sintaxis de la consulta SQL de Cosmos DB.

### 5.3 Código de la función

```javascript
module.exports = async function (context, myTimer) {

    if (myTimer.isPastDue) {
        context.log('El resumen semanal se ejecutó con retraso.');
    }

    const todas = context.bindings.todasLasResenas || [];

    // Filtrar reseñas de los últimos 7 días
    const hace7Dias = new Date();
    hace7Dias.setDate(hace7Dias.getDate() - 7);

    const recientes = todas.filter(r =>
        r.fechaCreacion && new Date(r.fechaCreacion) >= hace7Dias
    );

    if (recientes.length === 0) {
        context.log('No hubo reseñas en los últimos 7 días.');
        return;
    }

    // Agrupar por ISBN y calcular métricas
    const porISBN = {};
    recientes.forEach(r => {
        if (!porISBN[r.isbn]) {
            porISBN[r.isbn] = { isbn: r.isbn, cantidad: 0, sumaValoracion: 0 };
        }
        porISBN[r.isbn].cantidad++;
        porISBN[r.isbn].sumaValoracion += r.valoracion;
    });

    // Construir el ranking ordenado por cantidad de reseñas
    const ranking = Object.values(porISBN)
        .map(libro => ({
            isbn: libro.isbn,
            cantidadResenas: libro.cantidad,
            promedioValoracion: (libro.sumaValoracion / libro.cantidad).toFixed(1)
        }))
        .sort((a, b) => b.cantidadResenas - a.cantidadResenas);

    // En producción aquí se enviaría el ranking por email,
    // se guardaría en otra colección de Cosmos DB o se publicaría en una cola.
    context.log('Resumen semanal de reseñas:');
    context.log(`Total de reseñas en la semana: ${recientes.length}`);
    context.log('Ranking de libros más reseñados:');
    ranking.forEach((libro, i) => {
        context.log(`  ${i + 1}. ISBN ${libro.isbn} — ${libro.cantidadResenas} reseñas — promedio ${libro.promedioValoracion}`);
    });
};
```

Haz clic en **"Guardar"**.

## Lo que diferencia esta arquitectura

| Componente | Por qué este servicio |
|---|---|
| **Azure Functions** | Tráfico intermitente: nadie reseña a las 3 AM. Escala a cero y no genera costo en reposo. |
| **Cosmos DB** | Documentos con estructura variable. Cada reseña puede tener campos diferentes sin romper el esquema. |
| **PostgreSQL (existente)** | Los libros tienen esquema fijo (isbn, titulo, autor). Un servicio relacional es la elección correcta ahí. |
| **Bindings de salida/entrada** | No se escribe código de conexión ni de cliente HTTP. Azure gestiona la escritura y lectura declarativamente. |

Los dos sistemas coexisten: PostgreSQL guarda los libros con esquema estricto, Cosmos DB guarda las reseñas con esquema flexible. Cada servicio hace lo que mejor hace.

## Solución de problemas frecuentes

| Problema | Causa | Solución |
|---|---|---|
| `Cosmos DB connection configuration 'CosmosDB' does not exist` | El portal creó automáticamente la variable con el nombre `CosmosDB` pero no existe en la configuración de la app | Ir a la Function App → Variables de entorno → agregar `CosmosDB` con la cadena de conexión completa de Cosmos DB → Claves → CADENA DE CONEXIÓN PRINCIPAL |
| `Value cannot be null (Parameter 'containerId')` | El `function.json` usa `collectionName` en lugar de `containerName` | Abrir `function.json` en "Código y prueba", cambiar `"collectionName"` por `"containerName"` en todos los bindings de Cosmos DB y guardar |
| Error 500 inmediato (duración 1-5ms) | El `function.json` tiene el campo `"methods": []` en el binding de Cosmos DB, lo que lo invalida | Abrir `function.json` y eliminar la línea `"methods": []` del bloque del binding de Cosmos DB |
| `Error while accessing 'isbn': property doesn't exist` | El binding expression `{Query.isbn}` no resuelve query string de forma confiable en todos los runtimes | Usar parámetro de ruta: `route: "resenas/{isbn}"` en el trigger y `'{isbn}'` en el sqlQuery. Cambiar `req.query.isbn` por `req.params.isbn` en el código |
| La función devuelve 404 aunque hay documentos en Cosmos DB | El binding ejecuta un cross-partition query sin `partitionKey` y no encuentra los documentos aunque existan | Agregar `"partitionKey": "{isbn}"` en el bloque del binding de entrada en `function.json` |
| `context.bindings.resenas` llega vacío aunque hay documentos | La consulta SQL del binding tiene error de sintaxis o el isbn no coincide | Verificar en el Explorador de datos que el campo `isbn` del documento coincide exactamente con el valor enviado en la query string |
| El documento se guarda sin el campo `id` | Cosmos DB rechaza documentos sin `id` | El campo `id` debe estar en el objeto asignado a `outputDocument`; verificar que se genera en el código |
| El Timer no ejecuta el código correcto | Se editó el código pero no se guardó | Hacer clic en "Guardar" antes de esperar la ejecución |
| El Explorador de datos no muestra los documentos | Problema de permisos con Entra ID | Hacer clic en "Cambiar a la clave de acceso" en la barra del Explorador de datos |
